# DeepSeek 在可观测性智能体中的应用

云观秋毫团队（可观测性初创企业，产品 APO）在 2024 年将大语言模型引入故障定位流程，于 2024 年 11 月选型 DeepSeek 作为智能体背后的默认 LLM。^[extracted]

## 智能体工作流程

```
告警通知 → 告警和异常检测事件 → 大模型利用预设思维链规则
→ 分析拓扑和事件数据 → 识别疑似根因节点 → 北极星指标确认根因
```

这个流程替代了传统规则引擎，在可解释性、可扩展性上有显著提升。^[extracted]

## 大模型选型维度

### 1. JSON 格式数据的理解

可观测性数据以嵌套 JSON 为主（微服务拓扑关系）。精简数据、用嵌套 JSON 记录调用关系，能帮助大模型理解层级结构。但并非所有模型都能正确解析。^[extracted]

| 模型 | JSON 理解 |
|------|----------|
| 文言一心 | ❌ |
| 参数 14B 以下 | ❌ |
| 豆包 1.5-Pro-256K | ✅ |
| 智谱 GLM-4-Plus | ✅ |
| Qwen2.5-32B 及以上 | ✅ |
| **DeepSeek** | ✅ |

部分模型在理解 JSON 时容易出错：如将上下游调用关系搞反、忽略端点数据导致服务名不完整。^[extracted]

### 2. 自然语言规则执行准确率

大模型需要根据用户提供的自然语言规则推理定位故障。部分模型会偏离指令——例如忽略端点数据导致业务拓扑服务名不完整。^[extracted]

| 模型 | 规则执行准确率 |
|------|---------------|
| 豆包 1.5-Pro-256K | 70% |
| Qwen2.5-32B | 70% |
| 智谱 GLM-4-Plus | 90% |
| Qwen2.5-72B | 90% |
| **DeepSeek** | **100%** |

### 3. 使用成本

| 模型 | 输入价格 (千 Token) | 输出价格 (千 Token) |
|------|---------------------|---------------------|
| Qwen2.5-32B | ¥0.002 | ¥0.006 |
| Qwen2.5-72B | ¥0.004 | ¥0.012 |
| 智谱 GLM-4-Plus | ¥0.05 | ¥0.05 |
| 豆包 1.5-Pro-256K | ¥0.005 | ¥0.009 |
| **DeepSeek** | ¥0.0005(缓存)/¥0.002 | ¥0.008 |

DeepSeek 费用远低于同类旗舰模型，缓存命中时成本进一步降低。^[extracted]

## 存在的问题与缓解

### 幻觉现象

DeepSeek 在处理微服务拓扑时偶尔会输出不存在于真实数据中的服务名（如 "ts-payment-service"），这些名称在语义上与测试场景相关（train-ticket），属于模型联想偏差。^[extracted]

缓解措施 ^[extracted]：

1. **调整生成参数**：降低 `temperature`（减少随机性），调整 `top_p`（限制词汇选择范围）
2. **优化数据组织**：用"服务名 + 端点"的组合代替纯服务名标识节点，增加数据独特性，降低混淆概率

## 选型结论

DeepSeek 凭借对 JSON 数据的深入理解（通过）、100% 的规则执行准确率（领先 Qwen2.5-72B 的 90%）、以及极具竞争力的成本（输入成本为 Qwen2.5-72B 的 1/2 到 1/8），成为可观测性数据分析领域的理想选择。^[extracted]

## 行业影响

云观秋毫正在将实践经验平台化，研发可观测性智能体编排平台并计划开源，让用户能构建覆盖更多可观测场景的智能体。^[inferred]
