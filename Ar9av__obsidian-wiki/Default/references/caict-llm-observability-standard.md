# 中国信通院《面向LLM应用的可观测性能力要求》

2025 年 7 月 22 日，由中国信息通信研究院（简称"中国信通院"）联合行业各单位编制的标准《面向LLM应用的可观测性能力要求》于第十二届可信云大会主论坛正式发布，旨在规范和指导企业进行大模型应用可观测性能力建设。

## 标准背景

随着生成式 AI 技术的广泛应用，LLM 在对话系统、RAG、智能体等场景中展现出巨大潜力。然而，LLM 通常包含十亿甚至数万亿级别的参数，其应用在生产落地中仍面临着**模型不确定性大、架构链路复杂、用户体验难以评估**等痛点。如何构建大模型应用的全链路可观测性体系，如何评估 LLM 应用可观测性的能力是否完善，业界此前缺乏统一的标准。

中国信通院基于前期的多项研究工作，与各行业专家通过多轮讨论，制定出了**国内首个面向 LLM 应用的可观测性能力的分级要求**。

## 标准框架

标准面向 LLM 应用在训练推理过程中的可观测建设工作，以**数据的采集、建模、存储、应用**为主线，对各环节所需能力进行标准化规范。

标准框架分为**数据采集、数据模型、数据存储和数据应用**四大部分。数据模型层分为指标体系、日志和链路三个部分。

### 指标体系分层

| 层级 | 规范内容 | 关键指标 |
|------|----------|----------|
| **基础设施层** | LLM 应用运行的物理或虚拟资源底座 | 网络、存储、主机、操作系统、系统进程指标 |
| **中间件层** | 连接基础设施层与上层模型/应用的技术桥梁 | RAG、语义缓存、MCP、向量数据库指标 |
| **模型层** | LLM 应用的核心智能载体 | 模型指标、成本指标、评估指标、多模态评估指标 |
| **模型服务层** | 将模型能力转化为可调用的服务 | 性能指标、失败指标、计量指标 |
| **应用层** | LLM 技术面向终端用户的最终形态 | 性能指标、内容质量、用户体验指标、失败指标 |

## 模型服务层核心指标

### 1. 性能指标

- 支持监测模型服务的每秒处理请求量（QPS）
- 支持监测模型服务的请求响应时间
- 支持监测模型服务的输入/输出 Token 消耗数、输入/输出 Token 消耗速率
- 支持监测模型服务的**首 Token 延时（TTFT）**
- 支持监测模型服务的最大并发连接数
- 支持监测模型服务的吞吐量（单位时间内处理的数据量）

### 2. 失败指标

- 支持监测模型服务的服务失效率
- 支持监测模型服务的推理超时率
- 支持监测特定错误类型的出现频率（如模型内部错误、输入格式错误等）

### 3. 计量指标

- 支持按时间、消费者、模型维度统计模型服务的请求数
- 支持按时间、消费者、模型维度统计模型服务的输入/输出 Token 数

## 数据应用：会话分析

标准要求支持对 LLM 应用的会话数据进行分析，评估会话质量，确保会话安全与合规，优化会话管理和提高用户满意度：

1. **会话数据整合**：展示会话的上下文信息（开始时间、结束时间、会话时长）和用户终端基本信息（机型、操作系统、应用版本、分辨率等）
2. **会话响应时间分析**：分析从用户发起请求到收到响应的总时间，以及会话中各个处理阶段的响应时间（模型推理时间、数据传输时间等）
3. **会话准确性分析**：对单次会话进行钻取分析，评估 LLM 应用对用户意图的理解准确度
4. **会话一致性检查**：检查 LLM 应用在不同会话中对相同或相似问题的回答是否一致
5. **用户行为模式识别**：分析用户在会话中的行为模式（如频繁重复提问、提前结束会话等），评估用户对回答的满意度

## 首批评估

标准发布后，首批中国信通院《面向LLM应用的可观测性能力要求》标准评估已启动，评估流程包括：

1. **报名合同签订**：企业参考相关新闻、评测目录，确定评测意向
2. **技术对接**：安排测试人员对接，提供详细测试方法
3. **正式评测**：在正式排期内进行评测，多数须 1 个月内完成
4. **专家评审**：行业技术专家组成评审组，对参评企业及其产品报告进行评审
5. **证书颁发**：通过专家组评审后颁发首批评估证书
