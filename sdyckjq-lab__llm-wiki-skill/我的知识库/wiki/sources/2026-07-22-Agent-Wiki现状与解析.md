# Agent Wiki的现状与解析

## 核心观点

1. **编译而非检索**：LLM Wiki 将知识合成从查询时前移到摄入时。模型在摄入资料时一次性编译为持久化的 Markdown 页面，后续查询直接读取页面，而非每次从原始片段重新推导。

2. **四个独立实现趋同**：Cognition（DeepWiki）、Factory（AutoWiki）、LangChain（OpenWiki）和 Garry Tan（GBrain）四支团队在几个月内独立实现了同一架构——原始资料不可变、LLM 生成 Wiki、配置文件定义组织方式。趋同本身就是信号。

3. **瓶颈从来不是写作**：人类 Wiki 衰败的真正原因是维护成本（更新交叉引用、保持摘要最新、协调新旧页面），而语言模型恰好擅长这类无趣但无界的簿记工作。LLM Wiki 有效是因为它消除了维护成本。

4. **Wiki 不是记忆**：Wiki 编译的是语料库知识（"这份材料包含什么"），而非用户经验记忆（"我上周二改变了什么决定"）。两者互补，错误在于认为编译了语料库就解决了记忆问题。

5. **规模与局限性共存**：先索引且不使用嵌入的方法在约 100 个来源、几百个页面的中等规模下效果好，超过后需要引入真正的搜索。同时存在保真度损失（早期摘要可能丢失细节）、过时性（只在最后一次刷新时真实）和编译成本（预先支付 Token 构建可能永不被查询的页面）。

6. **文档应作为构建产物**：Factory 的 AutoWiki 提出了最明确的主张——文档应该是构建产物而非副项目，应从源码构建，在代码变更时自动刷新。这一观点将时效性从纪律问题变成了基础设施问题。

## 关键概念

- [[LLM Wiki]]：Andrej Karpathy 提出的模式——用 LLM 将知识编译为持久化 Markdown 页面
- [[Agent Wiki]]：LLM Wiki 模式在社区中演化的统称
- [[DeepWiki]]：Cognition 的实现，面向公共 GitHub 仓库
- [[AutoWiki]]：Factory 的实现，文档作为构建产物
- [[OpenWiki]]：LangChain 的开源实现，从代码扩展到个人知识库
- [[GBrain]]：Garry Tan 的个人规模开源实现
- [[知识编译]]：在摄入时一次性合成知识，而非查询时重复推导
- [[RAG vs Wiki]]：检索增强生成与知识编译的范式对比

## 原文精彩摘录

> "LLM Wiki将合成时机反转了。它不是从原始片段在查询时组装知识，而是让LLM在摄入时一次性将知识组装成持久化的页面，然后维护它们。"

> "人类维基会腐烂，原因很具体。困难的部分从来都不是阅读资料或拥有洞察力，而是簿记工作……而这正是语言模型不介意的工作。它不会厌倦，不会忘记更新交叉引用，并且可以在一次处理中修改十五个文件。"

> "当解决不同问题的独立团队落在相同的形状上时，这个形状通常是正确的。"

> "一个过时的维基比没有维基更糟糕，因为它以一种看起来权威的格式自信地出错。"

> "维基擅长第一个（语料库知识），并且不尝试第二个（用户经验记忆）。"
