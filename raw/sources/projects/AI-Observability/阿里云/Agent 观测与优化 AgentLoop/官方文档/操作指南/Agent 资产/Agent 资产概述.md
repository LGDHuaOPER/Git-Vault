LLM 应用迭代过程中，Prompt 与 Skill 的变更往往与代码部署耦合，难以独立追踪和回退。Agent 资产管理将 Prompt 与 Skill 作为独立资产进行版本化管理，支持多人协同编辑、灰度发布和效果对比。

## 资产管理的价值

| 能力  | 说明  |
| --- | --- |
| 与代码解耦 | 在 AgentLoop 上独立发布新版 Prompt 与 Skill，无需重新部署应用。 |
| 持续评估调优 | 版本化管理 Prompt 与 Skill，支持回归测试与历史对照，每次迭代基于数据驱动。 |
| 多岗位共建 | 设计、运营、产品等角色共同维护 Prompt 与 Skill，改动可追溯。 |
| 指标可比对 | 跨版本追踪延迟、Token 成本和评测指标，量化版本间的效果差异。 |

## 基本概念

每个 Agent 资产包含基本信息和版本信息两部分。基本信息描述资产本身，版本信息记录每次迭代的内容和状态。

### 基本信息

| 字段  | 说明  |
| --- | --- |
| 名称（Name） | 资产名称，在命名空间内唯一。 |
| 描述  | 资产的功能和用途说明。 |
| 创建时间 | 资产的创建时间。 |
| 版本信息列表 | 该资产下所有版本信息（VersionInfo）的集合。 |

### 版本信息（VersionInfo）

每个资产可包含多个版本，每个版本记录一次迭代的内容和状态。

| 字段  | 说明  |
| --- | --- |
| 版本号 | 建议采用 x.y.z 格式（语义化版本），也支持自定义格式。 |
| 状态（status） | 版本的当前状态。取值： - **草稿**：编辑中，可继续修改。 - **已发布**：内容已锁定，不可编辑。 |
| 更新时间 | 版本的最近修改时间。 |
| 变更日志 | 本次版本的变更说明。 |

### 版本指针

版本指针用于标记特定版本，在不同环境或场景中快速引用。AgentLoop 提供以下两种指针机制：

| 指针类型         | 说明                                                             | 典型用途        |
| ------------ | -------------------------------------------------------------- | ----------- |
| Latest 版本    | 自动跟踪最新的已发布版本。每次发布新版本后，Latest 指针自动更新，无需手动操作。                    | 获取当前最新稳定版本。 |
| 版本标签（Labels） | 自定义标签（如 Daily、Stable、Beta、Production），将标签绑定到指定版本。每个标签仅可标记一个版本。 | 灰度发布与环境隔离。  |
