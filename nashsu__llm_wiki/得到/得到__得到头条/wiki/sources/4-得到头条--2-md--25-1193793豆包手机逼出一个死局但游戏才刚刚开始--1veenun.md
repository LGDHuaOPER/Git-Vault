# 793｜豆包手机逼出一个"死局"，但游戏才刚刚开始

## 核心主张

1. **豆包手机的本质是"系统级权限"**：它让AI从"访客"变成拥有"万能钥匙"的操作者，能跨应用执行任务（投简历、点外卖等），这是质变。
2. **当前技术不成熟**：AI错误率高达30%-40%，远低于消费级产品95%的可靠性门槛。卓克认为需要"下一代全新原理的模型"才能解决。
3. **平台抵制是必然的**：AI助手会压缩用户停留时长（从10分钟到10秒），摧毁广告收入、推荐转化、交叉销售。微信的封禁（无论主动还是被动）是典型案例。
4. **短期博弈格局：囚徒困境**。所有平台都抵制看似稳定，但只要有1个平台开放，就会获得AI渠道的全部流量，迫使其他平台跟进。抵制联盟非常脆弱。
5. **中长期演化：演化博弈**。可能出现"AI原生应用"——不给人类看、只给机器用的服务。Stripe、Alexa、无头电商都是苗头。传统App与AI原生App将共存，而非一方消灭另一方。
6. **未来参与者**：手机厂商（控制OS）、AI公司（有AI能力）、超级App（有用户和频次）都可能参与竞争。
7. **核心判断**："命运的齿轮已经开始转动"，趋势不可逆，不会因当前产品不成熟而停止。

## 关键实体

| 名称 | 角色 |
|------|------|
| 豆包 | 字节跳动的AI助手，搭载于中兴合作手机上，具备系统级权限 |
| 字节跳动 | 豆包的开发公司，通过联合制造手机获取系统级权限 |
| 中兴 | 与字节合作制造豆包手机的硬件厂商 |
| 卓克 | 得到系老师，提供关于AI错误率与消费级产品可靠性的观点 |

| Alexa | 亚马逊的AI产品，被举例为语音购物的先行者 |
| 微信 | 超级App，被传封禁豆包助手，代表平台抵制力量 |
| 华为/小米/OPPO/vivo/荣耀 | 手机厂商，控制操作系统，不太可能将核心权限交给外部公司 |

## 关键概念

| 名称 | 定义 |
|------|------|
| 系统级权限 | AI助手获得操作系统层面的万能钥匙，可自由进出所有应用并操作设备功能 |
| 囚徒困境 | 博弈论经典场景：每个平台都选择抵制以保护自身利益，但只要有1个平台开放，抵制联盟就会瓦解 |
| 演化博弈 | 生态系统中不同策略相互竞争，市场自然选择出最适应环境的策略 |
| AI原生应用 | 不是给人看而是给机器用的应用，以结构化数据、清晰逻辑、标准化接口为核心，界面不重要 |
| 无头电商 | 前端与后端完全分离的电商模式，后端通过API提供所有功能，前端可以是任何设备 |
| 消费级产品可靠性门槛 | 95%以上可靠性才"可用"，99%以上才"好用" |

## 证据强度

- 技术错误率数据（30%-40%）和可靠性门槛（95%/99%）来自卓克，有一定专业依据，但未引用具体研究
- 微信封禁案例有官方回应佐证，但官方称是"被动触发安全风控"而非主动封禁
- Stripe、Alexa、无头电商等案例真实存在，但作为"AI原生"苗头的论证是推演性的
- 博弈论分析是框架性推演，非实证研究
- **整体证据强度：中等**。事实部分可靠，但核心预测属于推演。

## 内部张力

1. **技术不成熟 vs 趋势不可逆**：一方面承认错误率灾难性，需要"下一代模型"才能解决；另一方面断言"命运的齿轮已经开始转动，不会停下"。这两个判断之间存在时间差张力。
2. **平台抵制 vs 囚徒困境瓦解抵制**：微信等大平台有资本抵制，但囚徒困境逻辑预测抵制会瓦解。可能形成分化格局——小平台先开放，大平台继续抵制。
3. **AI原生App vs 传统App共存**：文章最终结论是共存，但前面的分析强调AI助手对传统App流量模式的摧毁性。共存的具体形态和边界未充分论证。
