| ** 类别 **** **** ** | ** 检查项 **** **** ** | ** 关键子项示例 **** **** ** |
| --- | --- | --- |
| ** 项目启动阶段 ** | 1. 项目章程是否正式签署（含目标、预算、关键干系人）？ | • 章程是否明确退出标准？ • 是否定义项目优先级（进度/成本/质量平衡）？ |
|  | 2. 是否完成干系人分析矩阵（权力、利益、态度）及管理策略？ | • 是否识别潜在反对者？ • 是否制定沟通定制化策略？ |
| ** 范围与需求管理 ** | 3. 需求文档是否通过正式评审（含功能/非功能需求）？ | • 需求是否可测试？ • 是否使用需求跟踪矩阵（RTM）？ |
|  | 4. 变更控制流程是否嵌入需求基线？ | • 是否定义紧急变更快速通道？ • 变更历史是否完整记录？ |
| ** 计划深度分解 ** | 5. WBS是否分解到工作包级别（≤80小时）？ | • 是否标注任务类型（决策类/执行类/协作类）？ • 是否定义任务验收标准？ |
|  | 6. 关键路径分析是否完成（CPM/PERT）？ | • 是否计算浮动时间？ • 是否识别并行任务优化点？ |
| ** 资源与成本精细化 ** | 7. 资源负荷是否进行模拟（资源直方图/燃尽图）？ | • 是否预留10-15%缓冲资源？ • 是否定义资源替代方案？ |
|  | 8. 成本估算是否采用多方法验证（类比/参数/自下而上）？ | • 是否包含应急储备和管理储备？ • 是否拆分直接成本与间接成本？ |
| ** 风险管理深度 ** | 9. 是否建立风险登记册（概率/影响/触发条件）？ | • 是否量化风险敞口（如预期货币值EMV）？ • 是否定义风险升级阈值？ |
|  | 10. 是否制定次生风险应对策略？ | • 是否关联主风险与次生风险？ • 是否定期刷新风险热图？ |
| ** 质量与测试体系 ** | 11. 是否建立质量测量指标（如缺陷密度、测试覆盖率）？ | • 是否定义质量门禁（如代码冻结标准）？ • 是否制定回归测试策略？ |
|  | 12. 测试环境是否与生产环境一致（数据隔离/权限管控）？ | • 是否包含性能测试场景？ • 是否定义缺陷优先级分类规则？ |
| ** 采购与供应商管理 ** | 13. 外包合同是否明确SLA（服务等级协议）及违约条款？ | • 是否定义知识产权归属？ • 是否设置供应商阶段性评审节点？ |
|  | 14. 是否制定供应商交付物验收流程？ | • 是否包含第三方审计条款？ • 是否建立备选供应商清单？ |
| ** 沟通与协作增强 ** | 15. 是否制定跨文化团队协作规范（时区/语言/工作习惯）？ | • 是否定义紧急事件沟通链？ • 是否使用协同工具（如Confluence、Slack）？ |
|  | 16. 会议管理机制是否高效（如每日站会/周报模板/决策日志）？ | • 是否提前分发议程？ • 是否指定会议纪要责任人？ |
| ** 合规与审计 ** | 17. 是否通过法律与合规性审查（数据隐私/行业法规）？ | • GDPR/CCPA等合规要求是否嵌入设计？ • 是否完成安全威胁建模？ |
|  | 18. 是否预设内外部审计时间点？ | • 审计检查表是否与项目计划同步？ • 是否定义整改响应时限？ |
| ** 收尾与知识沉淀 ** | 19. 是否制定项目收尾清单（合同关闭/资源释放/文档归档）？ | • 是否包含客户满意度调查？ • 是否完成经验教训库更新？ |
|  | 20. 是否规划运维支持过渡期（如知识转移/KPI交接）？ | • 是否定义缺陷响应SLA？ • 是否建立运维团队培训计划？ |
