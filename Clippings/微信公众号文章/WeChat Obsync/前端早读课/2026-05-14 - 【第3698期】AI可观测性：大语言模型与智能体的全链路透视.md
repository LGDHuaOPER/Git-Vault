# 【第3698期】AI可观测性：大语言模型与智能体的全链路透视

前言

AI 系统的非确定性让传统监控力不从心。AI 可观测性通过采集提示词、模型响应、工具调用等全链路遥测信息，为团队提供深度洞察，助力调试幻觉、控制成本、保障质量并满足合规要求，是构建可信赖 AI 应用的关键基石。

AI 可观测性是一种针对 AI 系统进行遥测数据采集、分析与关联的实践，旨在深入理解系统在开发和生产环境中的实际表现。应用于大语言模型时，称为 LLM 可观测性；应用于自主智能体时，则称为智能体可观测性。LLM 可观测性帮助团队追踪提示词质量、token 用量及响应准确度；智能体可观测性则助力调试多步骤工作流、工具调用与推理链路。

AI 可观测性为工程团队提供了对 AI 应用实际行为的深度洞察 —— 不仅能判断系统是否在运行，更能判断其输出是否正确、安全且有价值。随着 AI 系统从原型阶段迈向生产级关键应用，可观测性已成为保障质量与建立信任不可或缺的基石。

与传统软件不同，AI 应用具有非确定性：同样的输入可能因模型状态、检索到的上下文以及多步智能体推理的差异而产生截然不同的输出。这使得传统的日志记录和监控手段捉襟见肘。AI 可观测性能够捕获完整的执行上下文 —— 包括提示词、模型响应、工具调用、检索结果和评估分数 —— 从而让团队得以洞悉每一次输出背后的 "为什么"。

#### AI 可观测性的重要性

AI 系统 —— 包括智能体、大语言模型应用和 RAG 系统 —— 带来了传统软件监控无法应对的独特挑战：

##### 1、调试复杂性

**问题：** 多步骤智能体、工具调用和检索链路构成了错综复杂的执行路径，调试难度极高。

**解决方案：** 链路追踪让每一个步骤都清晰可见、可供调试 —— 从初始请求到最终响应，一览无余。

##### 2、成本控制

**问题：** 如果缺乏对使用模式和低效环节的可见性，token 成本很容易失控飙升。

**解决方案：** 通过追踪 token 用量、模型选择效率和单次请求成本，精准定位优化空间。

##### 3、质量与可靠性

**问题：** AI 系统可能产生幻觉、性能退化或质量下降的输出，从而损害用户信任。

**解决方案：** 在问题触达用户之前及时发现。自动将每一次响应与质量基准进行对照评估。

##### 4、合规与治理

**问题：** AI 系统所做的决策需要接受审计，且可能在无意中泄露个人隐私信息（PII）或违反内容政策。

**解决方案：** 维护完整的审计轨迹，并在整个 AI 技术栈中强制执行 PII 保护策略、内容安全护栏和访问控制机制。

#### LLM 可观测性

LLM 可观测性专注于监控单次大语言模型调用及基于 LLM 构建的应用。其涵盖范围包括：追踪发送给 GPT、Claude 或 Gemini 等模型的提示词，捕获模型返回的生成结果，度量 token 消耗与成本，以及监控响应延迟与质量。

对于 LLM 应用（如聊天机器人、内容生成器、摘要工具），可观测性帮助你了解哪些提示词能产出最佳结果，识别高成本或高延迟的查询，并在模型更新时及时发现质量退化。通过对每一次 LLM 调用进行完整上下文的追踪（系统提示词、用户消息、温度参数、token 计数），你可以调试幻觉问题、优化提示词模板，并追踪不同模型和使用场景下的成本分布。

MLflow 的自动追踪功能仅需一行代码即可采集上述所有遥测数据，并将追踪记录存储在本地或发送至追踪服务器，用于分析、评估和监控。

#### 智能体可观测性

智能体可观测性是 LLM 可观测性在多步骤智能体系统上的延伸。LLM 可观测性追踪的是单次模型调用，而智能体可观测性则捕获自主智能体的完整执行图谱：它们如何对任务进行推理，调用了哪些工具、以何种顺序调用，如何处理错误与重试，以及如何将多次 LLM 调用串联起来以完成复杂目标。

基于 LangGraph、CrewAI 或 AutoGen 等框架构建的智能体，其行为往往难以预测 —— 可能陷入死循环、做出错误的工具选择，或在不同运行中产生前后不一致的输出。智能体可观测性让每一步推理过程都透明可见：你可以清楚地看到哪些工具被调用、传入了什么参数、智能体从每一步中获取了什么信息，以及它如何决定下一步行动。

MLflow 能够自动追踪智能体工作流，捕获完整的有向无环图（DAG）执行结构，涵盖并行工具调用、条件分支和迭代推理循环。这使得调试智能体故障、优化智能体提示词与工具选择逻辑、以及监控智能体在生产环境中的行为都变得轻而易举。

#### AI 可观测性的常见应用场景

AI 可观测性在 AI 开发的全生命周期中解决着真实而具体的问题：

- 调试幻觉问题：当你的智能体、LLM 应用或 RAG 系统产生错误输出时，链路追踪能精确还原事件全貌 —— 检索了哪些文档、执行了哪些工具调用、发送了什么提示词、使用了哪些上下文。由此可以轻松判断问题究竟出在检索、推理、工具选择还是生成环节。
- 监控智能体的生产环境行为：智能体的行为可能出乎意料 —— 陷入循环、做出错误的工具选择，或产生不一致的输出。AI 可观测性平台自动捕获智能体的执行图谱，展示每一步推理、每一次工具调用和每一个决策节点，帮助你识别并修复问题模式。
- 优化 LLM 成本：追踪所有 LLM 调用的 token 用量与成本，识别高开销查询、低效提示词，或发现可以为特定任务切换至更轻量模型的机会。AI 可观测性平台帮助团队在不牺牲质量的前提下降低 30% 至 50% 的开支。
- A/B 测试提示词变更：在将提示词修改部署到生产环境之前，AI 可观测性平台支持使用 LLM 评判器进行并排对比评估。通过比较相关性、事实准确性和安全性等质量指标，确保变更是在提升而非削弱输出质量。
- 捕获生产环境退化：持续监控质量评分、错误率和延迟的变化趋势，在用户察觉之前，及时发现因 API 更新、提示词变更或数据漂移导致的模型行为退化。
- 保障合规性：捕获完整的审计轨迹，记录发送了哪些提示词、接收了哪些响应、访问了哪些数据。强制执行 PII 脱敏策略和内容安全护栏，以满足监管合规要求。

#### AI 可观测性的核心组件

一个完善的 AI 可观测性平台融合了六大核心能力：

- 链路追踪：记录请求执行的每一个步骤，涵盖每次 LLM 调用、检索和工具使用的输入、输出与延迟信息。
- 评估：利用自动化 LLM 评判器或自定义评分逻辑，对智能体和 LLM 应用进行并排对比，量化质量提升效果。
- 监控：通过 LLM 评判器追踪质量评分、错误率和漂移情况，借助在线监控机制尽早捕获性能退化。
- 成本与延迟追踪：监控每次请求的 token 消耗与成本，优化跨模型的支出与性能表现。
- 人工反馈：收集专家评审和终端用户评分，识别生产环境中的故障，并将其转化为防止回归的测试用例。
- 治理：维护提示词、响应及数据访问的完整审计日志，服务于合规审查与问题排查。

MLflow 等现代开源 AI 平台让你能够以极少的代码改动，为智能体、LLM 应用和 RAG 系统添加全面的、生产级别的可观测性能力。

只需一行代码，即可自动捕获每一次 LLM 调用的追踪数据，包括提示词、响应、token 用量、延迟和模型参数。这些追踪记录存储在本地或发送至 MLflow 追踪服务器，你可以在 MLflow 界面中对其进行搜索、筛选和分析。随后，你可以利用 LLM 评判器对追踪数据进行评估，发现幻觉和相关性不足等质量问题，监控生产指标以捕获退化，并调试故障。

以下是启用自动追踪的快速示例。请查阅 MLflow 追踪集成文档，了解如何在 LangChain、LangGraph、LlamaIndex、Vercel AI SDK 及其他框架中使用追踪功能。

**OpenAI**

```
import mlflow

# 为你的LLM框架启用自动追踪
mlflow.openai.autolog()

# 就这么简单——每一次LLM调用现在都会被追踪
from openai import OpenAI
client = OpenAI()
response = client.chat.completions.create(
model="gpt-5.2",
messages=[{"role": "user", "content": "Hello!"}],
)
```

**LangGraph**

```
import mlflow

# 为LangChain启用自动追踪
mlflow.langchain.autolog()

from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType

llm = ChatOpenAI(model="gpt-5.2")
agent = initialize_agent(tools, llm, agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION)
agent.run("What is the weather in San Francisco?")
```

**Vercel AI SDK**

```

model: openai('gpt-5.2'),

experimental_telemetry: { isEnabled: true }
});
```

#### 开源方案与商业方案的对比

在选择 AI 可观测性平台时，开源与商业 SaaS 工具之间的抉择将对你的团队、基础设施和数据所有权产生深远影响。

- 开源方案（MLflow）：使用 MLflow，你对可观测性基础设施和数据拥有完全的掌控权。可以部署在自有基础设施上，也可以使用 Databricks、AWS 或其他平台上的托管版本。没有按席位收费，没有使用量限制，没有供应商锁定。遥测数据始终在你的掌控之下，你可以根据自身需求对平台进行定制。MLflow 通过兼容 OpenTelemetry 的追踪机制，与任何 LLM 提供商和智能体框架无缝集成。
- 商业 SaaS 工具：商业可观测性平台提供了便利性，但代价是灵活性和控制权的丧失。它们通常按席位或追踪量收费，在大规模使用时成本高昂。你的数据会被发送到其服务器，引发隐私和合规方面的顾虑。你被锁定在其生态系统中，难以更换服务商或自定义功能。大多数商业工具仅支持部分 LLM 提供商和框架。

团队为何选择开源方案：构建生产级 AI 应用的组织越来越多地选择 MLflow，因为它在提供企业级可观测性的同时，不会在数据主权、成本可预测性和灵活性上做出任何妥协。Apache 2.0 许可证和 Linux 基金会的支持确保 MLflow 始终保持真正的开放性和社区驱动模式，不受任何单一供应商的控制。
